# Phase 27, Plan 1: Sub-LLM Integration & System Prompts

## Goal
Wire `RlmSession` (Phase 26) to real models through `@draht/router`, with
model-tiered system prompts and cost accounting per trajectory.

## Context
- `RlmSession` (packages/rlm/src/session.ts) already takes `rootLlm` and
  `llmQuery` as **injected callbacks** in `RlmSessionOptions` — this phase
  does not change `RlmSession` itself, it builds a router-backed factory
  that constructs those callbacks and passes them in. Don't touch
  `session.ts`'s core loop.
- `packages/router/src/types.ts`: `BUILT_IN_ROLES` is the fixed tuple that
  "must be present in every config" for *all* router usage, unrelated to
  RLM — do not add `rlm-root`/`rlm-sub` there. Instead add both as new
  entries in `DEFAULT_CONFIG` (a `Record<string, RoleConfig>`, already
  extensible via the `RouterRole = (typeof BUILT_IN_ROLES)[number] | (string
  & {})` type), same pattern as the 6 existing built-in roles.
  - `rlm-root` needs a large context window (root LM holds the growing
    history + metadata, and per R26-RLM.7 never the full context — but
    still benefits from a big window for headroom). Pick a 1M-context model
    as primary (e.g. `anthropic/claude-opus-4-6`, confirmed `contextWindow:
    1000000` in `packages/ai/src/providers/anthropic.models.ts`), with a
    fallback chain.
  - `rlm-sub` is called far more often (every `llm_query` from inside the
    REPL) and should default to something fast/cheap, with its own
    independent fallback chain — not tied to `rlm-root`'s chain.
- `packages/router/src/config.ts` already validates `ModelRef`s against
  `@draht/ai`'s registry (`getModels`/`getProviders` from `@draht/ai/compat`)
  — reuse that, don't hand-roll a second validation path.
- `packages/router/src/cost.ts`'s `CostEntry` has `sessionId` but no
  trajectory concept — add an optional `trajectoryId?: string` field
  (additive, non-breaking) and have the RLM cost-logging path populate it.
  Don't touch `estimateCost`/`logCost`'s existing behavior for non-RLM
  callers.
- Model context-window lookup for template auto-selection: `getModel(provider,
  modelId)` from `@draht/ai/compat` returns a `Model` with `contextWindow`
  (see e.g. `contextWindow: 1000000` / `200000` in the provider `.models.ts`
  files) — use the *resolved* primary model's `contextWindow`, not a
  hardcoded guess.
- The referenced paper (arXiv:2512.24601) Appendix C.1 isn't available to
  read directly in this environment — write the three prompt templates from
  the technique's already-documented mechanics (this repo's own
  REQUIREMENTS.md R26-R30 blocks describe the mechanism precisely: root LM
  writes Python peeking/chunking/searching `context`, calls `llm_query` for
  recursive sub-calls, terminates via `FINAL`/`FINAL_VAR`). Don't invent
  citations to paper sections you can't verify; describe the templates by
  what they do, not by claimed exact paper provenance.

## Architecture

### 1. Router roles (`packages/router/src/types.ts`)
Add to `DEFAULT_CONFIG`:
```ts
"rlm-root": {
  primary: { provider: "anthropic", model: "claude-opus-4-6" },
  fallbacks: [{ provider: "google", model: "gemini-2.5-pro" }],
},
"rlm-sub": {
  primary: { provider: "google", model: "gemini-2.5-flash" },
  fallbacks: [{ provider: "openrouter", model: "deepseek/deepseek-v3.2" }],
},
```
(Adjust models only if the ones above fail `config.ts`'s registry
validation — keep the *shape* and the tiering intent: root = large-context
frontier, sub = fast/cheap.)

### 2. Cost entry trajectory tagging (`packages/router/src/types.ts`, `cost.ts`)
Add `trajectoryId?: string` to `CostEntry`. No other change to `cost.ts`.

### 3. Prompt templates (`packages/rlm/prompts/`)
Three markdown files: `frontier.md`, `coder-mid.md`, `small-context.md`.
Each contains placeholder tokens `{{context_type}}`, `{{context_total_length}}`,
`{{chunk_lengths}}`, `{{max_sub_call_budget}}`, `{{sub_call_char_budget}}`,
plus a batching advisory: explicitly warn against issuing one `llm_query`
call per tiny item (e.g. per-line or per-record) and instead recommend
batching into ~10-15k character chunks per sub-call. The three templates
differ in verbosity/scaffolding detail (frontier: terse, assumes strong
planning; coder-mid: more explicit step-by-step guidance; small-context:
most explicit, smallest working-memory assumptions, shortest chunk-size
suggestions) — not just copy-pasted three times.

### 4. Template loading + selection (`packages/rlm/src/prompts.ts`)
```ts
export type PromptTier = "frontier" | "coder-mid" | "small-context";
export function selectTier(contextWindow: number): PromptTier; // e.g. >=500_000 -> frontier, >=128_000 -> coder-mid, else small-context — pick real thresholds and justify them in the summary
export function renderPrompt(tier: PromptTier, vars: { contextType: string; contextTotalLength: number; chunkLengths: number[]; maxSubCallBudget: number; subCallCharBudget: number }): string;
```
`renderPrompt` does simple `{{token}}` substitution (no templating engine
dependency needed for this).

### 5. Router-backed session factory (`packages/rlm/src/router-session.ts`)
```ts
export interface CreateRouterBackedSessionOptions {
  prompt: string;
  router: ModelRouter; // from @draht/router, caller-supplied so tests can inject a fake
  contextType?: string; // default "text"
  maxSubCallBudget?: number;
  subCallCharBudget?: number;
  costLogPath?: string; // passthrough to logCost
  sessionId?: string; // for CostEntry.sessionId
}
export function createRouterBackedSession(opts): RlmSession;
```
Builds `rootLlm`/`llmQuery` callbacks that call `router.complete("rlm-root"
| "rlm-sub", ...)` (match whatever the actual `ModelRouter` method is
named — read `packages/router/src/router.ts`'s public API first), selects
the prompt tier from the resolved `rlm-root` model's `contextWindow`,
renders the system prompt with the real prompt's length/chunk info, and
after every router call (both root and sub) computes a cost entry via
`estimateCost`/`logCost` from `@draht/router`, tagged with a single
`trajectoryId` generated once per session (`randomUUID()`) shared across
every call that session makes.

## Risks
- Don't guess `ModelRouter`'s real method name/signature — read
  `packages/router/src/router.ts` before writing the factory; a wrong
  assumption here breaks task 3 silently until integration.
- Keep `rlm-root`/`rlm-sub`'s model choices whatever passes real registry
  validation in `config.ts` — if `claude-opus-4-6` or `gemini-2.5-pro`
  aren't in the current `@draht/ai` registry, pick registry-valid
  equivalents that preserve the large-context-root / fast-cheap-sub intent
  and say what you picked and why in the summary.
