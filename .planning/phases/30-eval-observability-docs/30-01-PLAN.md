# Phase 30, Plan 1: Evaluation, Observability & Docs

## Goal
Make RLM trajectories measurable, replayable, and documented — the final
phase closing out the Recursive Language Models milestone (Phases 26-30).

## Context
- `createRouterBackedSession` (`packages/rlm/src/router-session.ts`,
  Phase 27) already generates one `trajectoryId` per session
  (`randomUUID()`) and tags every cost entry with it via `@draht/router`'s
  `estimateCost`/`logCost`. Reuse this exact `trajectoryId` as the
  trajectory JSONL's filename — don't invent a second identifier scheme.
- `RlmHistoryEntry` (`packages/rlm/src/types.ts`) already has `step`,
  `code`, `truncatedStdout`, `error`, `timestamp` — constant-size per
  R26-RLM.7. Trajectory logging is additive on top of this (a JSONL file,
  not a change to the in-memory history shape that feeds back into
  `rootLlm`).
- Don't touch `packages/rlm/python/repl_driver.py`'s protocol or
  `session.ts`'s core loop — this phase wraps/observes, per every prior
  phase's established non-rewrite convention.
- The `draht rlm` CLI subcommand already exists (Phase 29,
  `packages/coding-agent/src/rlm-cli.ts`, dispatched from `main.ts`) — add
  `replay` as a second mode of that same subcommand
  (`draht rlm replay <trajectory-id>`), don't create a separate CLI entry
  point.

## Architecture

### 1. Trajectory JSONL logging (`packages/rlm/src/trajectory.ts`)
```ts
export interface TrajectoryStepEntry {
  type: "step";
  trajectoryId: string;
  step: number;
  code: string;
  truncatedStdout: string;
  error: string | null;
  subCalls: Array<{ costUsd: number; provider: string; model: string }>; // sub-LLM calls made *during* this step
  costUsd: number; // this step's own root-call cost + sum of its subCalls
  timestamp: string;
}
export interface TrajectoryFinalEntry {
  type: "final";
  trajectoryId: string;
  kind: RlmResultKind; // from types.ts
  value: unknown;
  totalCostUsd: number;
  totalSteps: number;
  timestamp: string;
}
export function appendTrajectoryEntry(trajectoryId: string, entry: TrajectoryStepEntry | TrajectoryFinalEntry, logDir?: string): void; // default .draht/rlm/
export function readTrajectory(trajectoryId: string, logDir?: string): { steps: TrajectoryStepEntry[]; final: TrajectoryFinalEntry | null };
```
Wire this into `createRouterBackedSession` (Phase 27): after each step
resolves (root call + any sub-calls it triggered), append one
`TrajectoryStepEntry` correlating that step's sub-calls (you'll need to
track which `llm_query`/sub-call cost entries happened during which step —
the simplest correct approach is to accumulate sub-call cost entries since
the last step boundary and attach them to the step that triggered them,
not to try to retroactively correlate via timestamps). After `run()`
resolves, append one `TrajectoryFinalEntry`.

### 2. S-NIAH regression suite (`packages/rlm/test/s-niah.test.ts`)
Synthetic needle-in-haystack at two scales relative to a *mocked* root
model's context window (pick a round number, e.g. treat the mocked model as
if it had a 100,000-token/400,000-character window for this test's math,
and say so explicitly in a comment):
- 10x: ~4,000,000 characters of filler with one planted needle.
- 100x: ~40,000,000 characters of filler with one planted needle.
Use a **scripted mock `rootLlm`** (not a real model call) that behaves like
a plausible RLM strategy: peeks at `context`'s length, chunks/searches it
via Python string operations across a few turns, and calls `FINAL(...)`
once it locates the needle. Assert the correct value is recovered (recall)
at both scales, and assert the test completes in a reasonable wall-clock
time (large strings shouldn't make the *test infrastructure* slow, even
though a real root LLM run would take many turns — keep the mock's turn
count small and deterministic).

### 3. Cost-comparison harness (`packages/rlm/src/cost-comparison.ts` + a report)
```ts
export interface CostComparisonResult {
  task: string;
  rlmCostUsd: number; // sum of a trajectory's cost entries (via readCostLog/getSessionCosts from @draht/router, filtered by trajectoryId)
  baselineCostUsd: number; // estimated cost of truncating context to fit the root model's window and making one single call, via @draht/router's estimateCost
  rlmSteps: number;
  contextLengthChars: number;
}
export function compareCost(trajectoryId: string, contextLengthChars: number, model: { provider: string; modelName: string; contextWindow: number }, costLogPath?: string): CostComparisonResult;
```
Write a small eval script/test (`packages/rlm/test/cost-comparison.test.ts`)
that runs one `createRouterBackedSession` trajectory (mocked router, so no
real spend) against a synthetic oversize task, then calls `compareCost` and
asserts the returned structure is well-formed and the two costs are
computed from the described formulas (not that RLM is necessarily cheaper
in this synthetic case — the *harness* is what's required, not a specific
cost verdict). Write the comparison to
`.draht/rlm/cost-comparison-report.json` (or similar) as the "eval report"
R30-EVAL.3 asks for.

### 4. `draht rlm replay <trajectory-id>` (extend `packages/coding-agent/src/rlm-cli.ts`)
Add a `replay` subcommand mode: reads
`.draht/rlm/<trajectory-id>.jsonl` via `readTrajectory`, prints the final
answer (and optionally a step-by-step trace with a verbose flag), and
**makes zero network/LLM calls** — assert this explicitly in the test (no
router/model dependency reachable from the replay code path at all, not
just "happens not to call one in this test").

### 5. Docs (`packages/rlm/README.md`, plus an AGENTS.md section)
- When to prefer RLM over a normal agent read (oversize inputs that don't
  fit in a model's context window, or where truncation would lose
  relevant content).
- Cost envelope: RLM makes multiple LLM calls (root + potentially many
  sub-calls) vs. one call for a normal read — cheaper only when avoiding a
  bigger context/re-read cost, not universally cheaper; point at the cost-
  comparison harness (section 3) as how to check for a specific case.
- One worked end-to-end example (a realistic oversize-log-file or
  oversize-doc scenario) showing the `/rlm`, `draht rlm --input ... --query
  ...`, and `rlm_query` tool forms side by side.
- Find the relevant AGENTS.md template(s) from `packages/templates/` (Phase
  4) and add a short RLM section if appropriate, or note in the summary if
  none of the existing templates are the right place for it.

## Risks
- Don't let the 100x S-NIAH fixture generation itself become slow/flaky —
  generate filler text with simple repeated content, not something
  computationally expensive per character.
- Cost-comparison's "baseline" is inherently a rough estimate (truncation
  strategy for a single call isn't fully specified elsewhere in this
  codebase) — document the specific truncation approach you use (e.g.
  "first N characters that fit the window" vs something smarter) rather
  than presenting it as more precise than it is.
