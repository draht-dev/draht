## Files Changed
- `packages/rlm/src/trajectory.ts` — new module. `TrajectoryStepEntry` (`type: "step"`, `trajectoryId`, `step`, `code`, `truncatedStdout`, `error`, `subCalls: Array<{ costUsd, provider, model }>`, `costUsd`, `timestamp`) and `TrajectoryFinalEntry` (`type: "final"`, `trajectoryId`, `kind: RlmResultKind`, `value`, `totalCostUsd`, `totalSteps`, `timestamp`). `appendTrajectoryEntry(trajectoryId, entry, logDir?)` appends one NDJSON line to `<logDir ?? .draht/rlm/>/<trajectoryId>.jsonl` (creating the directory if needed); `readTrajectory(trajectoryId, logDir?)` reads the file back into `{ steps, final }`. Re-exported from `packages/rlm/src/index.ts` so `draht rlm replay` and any external consumer import via the public `@draht/rlm` entry point rather than reaching into `src/`.
- `packages/rlm/src/router-session.ts` — `createRouterBackedSession` gained an additive `trajectoryLogDir?: string` option (no breaking change to the existing options shape). Added a `StepCostAccumulator` (`rootCostUsd`, `subCalls`) tracked per in-flight step: `logRouterCall` now returns the `estimatedCostUsd` it computed instead of `void`, so the root call's own cost and every `llm_query` sub-call's cost occurring between one `rootLlm` invocation and the next can be accumulated onto `pendingStep`. `finalizeStepIfPending(history)` closes out the *previous* step's accumulator (root cost + sum of its sub-calls) into one `TrajectoryStepEntry` the moment the history array shows that step actually completed — called both before starting the next step's `rootLlm` call and once more after `run()` resolves, so the last step is never left unflushed. After `run()` resolves, one `TrajectoryFinalEntry` is appended with `totalCostUsd` (running sum of every finalized step's `costUsd`) and `totalSteps`. Sub-calls are attributed to the step that triggered them via this accumulate-since-last-boundary approach (not retroactive timestamp correlation), per the plan's explicit guidance.
- `packages/rlm/src/index.ts` — re-exports `TrajectoryFinalEntry`/`TrajectoryStepEntry` types and `appendTrajectoryEntry`/`readTrajectory` functions from `./trajectory.js`.
- `packages/rlm/test/trajectory.test.ts` — round-trip test for `appendTrajectoryEntry`/`readTrajectory` against a temp `logDir` (step + final entries); a full `createRouterBackedSession` trajectory (mocked router) producing exactly one step entry per actual step and exactly one final entry; a step with 2 sub-calls asserting both costs are summed into that step's `costUsd` and listed in its `subCalls` array (not misattributed to an adjacent step); the final entry's `totalCostUsd` equals the sum of all step costs.
- `packages/rlm/test/s-niah.test.ts` — new synthetic needle-in-haystack regression suite. Treats the mocked root model as if it had a 100,000-token / 400,000-character context window (stated explicitly in-file, per the plan's requirement not to imply this is a real model's window). Generates ~4,000,000 characters of filler (10x) and ~40,000,000 characters of filler (100x) via cheap repeated-content generation (not per-character computation, to keep fixture generation itself fast), each with one planted needle sentence at a fixed offset. Drives a scripted mock `rootLlm` that peeks at `len(context)`, does a small deterministic number of chunked/searched Python string-operation turns, and calls `FINAL(...)` once the needle is located — asserts the correct value is recovered at both scales and that the test itself completes quickly (the mock's turn count is small and deterministic; a real root LLM run would take more turns, but that's not what this test is measuring).
- `packages/rlm/src/cost-comparison.ts` — new module. `CostComparisonResult` (`task`, `rlmCostUsd`, `baselineCostUsd`, `rlmSteps`, `contextLengthChars`). `compareCost(trajectoryId, contextLengthChars, model, costLogPath?)`: `rlmCostUsd` sums a trajectory's own cost-log entries via `@draht/router`'s `readCostLog`/`getSessionCosts`, filtered by `trajectoryId`; `baselineCostUsd` estimates the cost of a single call that truncates `contextLengthChars` down to the target model's context window using a named, explicitly-documented "first-N-characters-that-fit" truncation strategy, then calls `@draht/router`'s `estimateCost`. Writes the comparison to `.draht/rlm/cost-comparison-report.json` as the eval report artifact.
- `packages/rlm/test/cost-comparison.test.ts` — runs one `createRouterBackedSession` trajectory (mocked router, no real spend) against a synthetic oversize task, then calls `compareCost` and asserts the returned structure is well-formed and both cost numbers are computed from the documented formulas — not asserting RLM is necessarily cheaper in this synthetic case, per the plan's explicit scope ("the harness is what's required, not a specific cost verdict").
- `packages/coding-agent/src/rlm-cli.ts` — added a `replay` mode alongside the existing Phase 29 `--input`/`--query` mode of the same `draht rlm` subcommand (not a separate CLI entry point). `draht rlm replay <trajectory-id>` calls `readTrajectory` directly, prints the final answer (plus a step-by-step trace under a verbose flag), and does not construct or reference a `ModelRouter`/session at all on that code path — the strongest available proof it makes zero network/LLM calls, since there is no router/model object reachable from the replay branch to accidentally invoke.
- `packages/coding-agent/test/rlm-cli.test.ts` — extended (Phase 29's existing 3 cases untouched) with: `draht rlm replay <trajectory-id>` against a pre-written trajectory JSONL fixture in a temp dir prints the correct final answer; an explicit assertion that no router/model wiring is passed anywhere on the replay path and it still produces the correct output; a nonexistent trajectory id produces a clear error message rather than a crash/stack trace.
- `packages/rlm/README.md` — rewritten from the Phase 26-era "scaffold only" placeholder into full documentation: "When to prefer RLM over a normal agent read" (oversize inputs that don't fit context, or where truncation risks losing relevant content, vs. normal reads for anything that already fits comfortably); "Cost envelope" (RLM's cost is `sum(root-step costs) + sum(sub-call costs)` vs. one baseline call — not universally cheaper, wins only when avoiding truncation-induced failure or repeated re-reads; points at `compareCost()` to measure the specific case rather than assume); "Observability: trajectory logs & replay" (every `createRouterBackedSession` run writes `.draht/rlm/<trajectoryId>.jsonl`; `draht rlm replay` reconstructs the answer with zero LLM calls; the S-NIAH suite as a standing recall check); a "Worked example" section showing the `/rlm`, `draht rlm --input ... --query ...`, and `rlm_query` tool forms side by side against a realistic oversize-log-file scenario; a "Package layout" map of all `src/*.ts` files plus the `rlm-cli.ts`/`rlm-agent` integration points; and an explicit "AGENTS.md" section stating the decision *not* to add an RLM note to any of `packages/templates/src/*.md`'s per-stack templates (Astro/Go-gRPC/SST-TypeScript) — RLM is a cross-cutting coding-agent capability, not a per-stack convention, and none of those templates nor this repo's own contributor-workflow `AGENTS.md` is the right home for it, so this README remains the primary documentation surface, per the plan's explicit fallback instruction.

## Notes
- **`trajectoryLogDir` is additive, not breaking.** `createRouterBackedSession`'s existing options shape (Phases 27-29) is unchanged for any caller that doesn't pass it — it defaults to `.draht/rlm/` inside `appendTrajectoryEntry` itself, matching the plan's explicit constraint not to touch `session.ts`'s core loop or the options contract in a breaking way.
- **Sub-call attribution uses accumulate-since-last-step-boundary, not timestamp correlation.** The plan flagged this as "the simplest correct approach" precisely because `rootLlm` is always called once per step, strictly before that step's own `llm_query` sub-calls occur (via the driver's `runExec`, itself only invoked by `session.ts` after `rootLlm` resolves) — so accumulating cost entries between one `rootLlm` call and the next always attributes them to the correct step, with no retroactive timestamp-matching logic that could misattribute a sub-call under clock skew or fast concurrent calls.
- **The cost-comparison "baseline" is explicitly a named, simple strategy** ("first-N-characters-that-fit"), not presented as the smartest possible truncation approach — per the plan's own risk note that this baseline is inherently a rough estimate absent a more sophisticated truncation strategy elsewhere in the codebase.
- **S-NIAH's "10x/100x a context window" is stated against a mocked 100,000-token/400,000-character window**, explicitly documented in-file as a round number chosen for this test's math, not a real model's actual window size — avoiding an implicit false claim about any specific provider's real context limit.
- **`draht rlm replay` provable zero-LLM-calls property comes from the replay branch never constructing a router/model object at all**, not merely "happening not to call one" in the test — the strongest form of the proof the plan asked for, mirroring the same class of empirical rigor Phase 29's `real-session-loading.test.ts` used for its own must-have claim.
- **No `packages/templates/` changes were made**, and the decision not to make any is written directly into `packages/rlm/README.md`'s new "AGENTS.md" section (see Files Changed) rather than only stated in this summary, so a future reader of the README itself sees the reasoning without needing to consult phase history.

No RLM feature work beyond eval/observability/docs was in scope, and none was added — per the plan's explicit Out of Scope section. The `packages/knowledge`/`packages/ci`/`packages/deploy-guardian` extension-loading finding flagged in Phase 29's summary remains unfixed and is still recommended as a follow-up for a future phase (unrelated to this milestone).
