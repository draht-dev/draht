## 1. Product shape

One transactional installer product for the whole Draht surface:

- **Engine:** `@draht/install` (new workspace package `packages/install/`), a library + CLI carrying both product bins — `draht-install` (machine-level component management: `plan`, `install`, `status`, `doctor`, `update`, `uninstall`) and `draht-init` (project bootstrap: ensure components, scaffold `.planning/` via the bundled `draht-tools` CLI, hand off to the agent). Single entry, basename dispatch. No bin named `draht` (unscoped npm `draht` is third-party; the `draht` bin belongs to `@draht/coding-agent`).
- **State:** hash-manifested, schema-versioned `state.json` under `~/.draht/install/` (`DRAHT_INSTALL_DIR` override), with an append-only JSONL journal, staged/backed-up transactional applies, automatic rollback on failure, and crash-transaction detection. All state writes are temp-file + atomic rename (deliberately stronger than the existing `settings-manager.ts` in-place pattern).
- **Components are data:** a zod-validated component index ships with the engine (`claude-plugin`, `codex-plugin`, `coding-agent`, `installer`); adapters are keyed by `kind`, never by package name. Adding a future org package of a supported kind is one data entry — no engine code. Unknown kinds fail closed only when selected.
- **Profiles:** default = detection-based (plugin payloads for harness CLIs actually present, plus the installer component); `--full` = everything; explicit selectors replace the default set; `--fail-on-empty` guards CI against silent empty-profile no-ops.
- **Canonical skills:** repo-root `skills/` is the provider-neutral Agent Skills source of truth (27 skills: 9 disciplines + 17 workflow skills + new `draht` umbrella/router). `packages/draht-claude` and `packages/draht-codex` skill/command content is **generated** from it via a dialect table; byte-equality checks (`check:skills-artifacts`, `prepublishOnly`) replace the old tolerance-based mirror gate. The `skills` CLI's priority walk short-circuits on a root `skills/` dir, so the public catalog becomes exactly the canonical set (verified mechanism, agentskills `skills@1.5.22`).
- **Update honesty:** updates are explicit (`draht-install update`); nothing writes outside an explicit command. Effectiveness is reported per host in five states (`live | after-reload | next-session | restart-required | unknown`); Codex reload semantics are `unknown` until verified. No claim that any host hot-updates. Opt-in scheduled updates are a deferred capability recorded in the policy model, never default-on.

## 3. Engine architecture (implemented shape)

- `src/types.ts` — zod schemas: `InstallState` v1 (channel, profile, per-component `{id, kind, version, source{npmName, resolvedVersion, integrity}, files[{path, sha256}], delegated?, registered?, effectiveness}`), `PlanAction` (install/update/remove/delegate-install/delegate-uninstall), `JournalEntry` (`planned → staged → backed-up → swapped → registered → committed | rolled-back`), `DoctorFinding {id, severity, message, repairable}`.
- `src/paths.ts` — state root resolution; `state.json`, `journal.jsonl`, `cache/`, `staging/<tx>/`, `backups/<tx>/`.
- `src/state.ts` — fresh-default load, typed corruption errors, atomic temp+rename+fsync writes (kill-proven by subprocess SIGKILL test).
- `src/journal.ts` — O_APPEND single-line records with fsync; reader tolerant of a torn final line; replay + open-transaction detection.
- `src/plan.ts` — pure, deterministic diff of desired (profile ∪ selectors, channel) vs actual (state + injected disk hashes): fresh→install, semver-lower→update, equal+hash-clean→no-op, drift→reinstall, desired-lower→typed `blocked: downgrade` (never silent), removes only under `prune`.
- `src/executor.ts` — per-transaction: stage → journal → backup (rename, EXDEV copy fallback) → atomic swap → register callback → verify → commit; any failure restores every backup byte-identically, journals `rolled-back`, leaves `state.json` untouched; named checkpoints are the fault-injection seam; leftover staging/backups + journal open-tx feed doctor.
- `src/sources/` — `RegistryClient` interface; npm-registry implementation (packument fetch honoring `DRAHT_REGISTRY`, dist-tag resolution, tarball download verified against **registry-served `dist.integrity`** (ssri sha512 — the npm trust root; catalog-supplied hashes were rejected as circular by the updater plan's refutation pass), cache keyed by integrity); local/fixture source for hermetic tests.
- `src/detect.ts` — harness CLIs on PATH, legacy curl-clone (`~/.draht/.git`), `~/.local/bin/draht` wrapper, `~/.pi` legacy state; typed findings consumed by plan/doctor.
- `src/adapters/` — keyed by kind. `claude-plugin`: stages the payload into `~/.draht/claude-marketplace/` and drives the verified call sequence of `draht-claude/cli.mjs` (validate→marketplace add→marketplace update→[force: uninstall]→`plugin install --scope user` (the one hard call)→enable), with **deregistration verified before local deletion on uninstall** (fixing the allowFail-then-delete hazard at `cli.mjs:305-320`). `codex-plugin`: mirror (marketplace add→[force: remove]→add). `global-cli`: delegated install via detected PM, recorded in state, honest failure; used by both the `coding-agent` and `installer` components.
- `src/doctor.ts` — catalogue (each `{id, severity, message, repairable}`): node/npm presence, state/journal integrity, manifest drift, legacy curl-clone, wrapper shadowing, `~/.pi` legacy state, harness presence for installed components, crashed transactions, installed-payload manifest-version drift.
- `src/cli.ts` — basename dispatch; verbs per §1; `--json` single documents with `schemaVersion` (NDJSON event stream on `install --json`); mutating verbs require a TTY or `--yes`; read verbs never prompt; short flags only `-h/-y/-n`.

Test posture: every test hermetic under `mkdtemp` roots with stubbed `claude`/`codex`/PM executables on a controlled PATH and a local fixture registry; zero live-network access; the lifecycle e2e packs the real tarball and drives plan→install→status→drift→doctor→uninstall to a byte-clean fake HOME.

## 4. Skills canonicalization (implemented shape)

- Canonical tree `skills/`: 9 disciplines (neutralized from the draht-claude copies — identity word and the `gsd-workflow` plugin-root line are the only host spans; 5 pairs were already byte-identical), 17 workflow skills as `<cmd>/{SKILL.md, command.md}` (SKILL.md from today's codex wrappers with the dangling `../../commands/` reference fixed to in-dir `./command.md`; command.md from today's claude command bodies with dispatch spans neutralized), plus the new `draht` umbrella/router skill.
- Generator `scripts/generate-skills-artifacts.mjs`: walks `skills/` dynamically (**no hardcoded skill list** — a new canonical skill dir is picked up automatically; this is the saga-spawner on-ramp), renders per host through a dialect table of (canonical → claude, codex) span triples derived from the observed pair diffs. Migration acceptance: regenerated Claude artifacts byte-identical to today's committed files; codex diffs are exactly the 17 wrapper rewrites + 17 in-dir `command.md` additions; both packages additionally gain `skills/draht/`.
- Checks: `check:skills-artifacts` (regenerate + byte-compare, exit 1 on drift) wired into root `npm run check` and both plugin packages' `prepublishOnly` (closing the verified gap that `release.mjs` never runs `npm run check`); `check-plugin-mirrors.mjs` reduced to its agents/ byte-identity check.
- Catalog effect on merge to the public mirror: default `skills` CLI discovery = exactly the canonical 27 (root-dir short-circuit); `--full-depth` consumers get canonical copies as dedup winners.

## 6. Standing risks & gates (carried from the plans, still true)

- **`fix/final-*`/`fix/review-*` branch family** (17 branches, tips 2026-08-05) rewrites `draht-claude/cli.mjs`, `draht-codex/cli.mjs`, `publish-workspaces.mjs`, `install.sh`. No `packages/install/` exists on any of them (verified by the product plan), so the architecture is unaffected — but the adapter-parity call sequences and the release/install.sh baselines must be re-verified against whatever has merged before the publish step. The engine's pinned-sequence adapter tests make any drift loud.
- **Post-publish npx shadowing**: once global engine bins exist, bare `npx draht-install` stops consulting the registry (npm global-bin shortcut); docs will standardize `npx draht-install@latest`; doctor gains the shadow-state notice with the launcher packages.
- **Windows**: rename-discipline behaviors untested on Windows (no Windows CI); documented limitation.
- **One-day CalVer transition edge**: on a day that already has a bare-form release, the first always-suffixed successor sorts below it for semver comparators until the next day; `latest` dist-tag unaffected.
