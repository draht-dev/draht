Pico5

Durable documents without a whole-session DOM

Usage, state → view, and why Lane stops short

The target is not one coding session

Products

  • coding agent
  • personal assistant
  • cloud agents in Durable Objects
  • Slack bots across years of channels and threads

Required invariants

  • survive process death mid-effect
  • fork historical conversation state
  • attach many presentations
  • let facets persist application state without inventing storage

Lane solved a real problem

Execution

Complete operation-state replacements make recovery a switch, not inference.

Effects

Durable intent → uncertain effect → durable outcome.

Transactions

Entries, values, and lists commit atomically in memory, JSONL, and SQLite.

Keep those properties. Replace the application-state substrate.

Lane exposes values and lists

const review = value<ReviewState>("app.review", id);
const findings = list<Finding>("app.findings", id);

await session.setValue(review, completeNextReview, context);

await session.deleteList(findings, context);

  • A list appends or is deleted whole.
  • Nested changes, splices, checkpoints, and reconstruction belong to the caller.

Lane forks transcript, not application state

branch A:  e1 ─ e2 ─ e3 ─ e4
                         └──── fork at e3 → branch B

value("plan-mode")       current replacement only
list("canvas-strokes")   surviving elements only

question: what was either value at e3?    not representable

The JSONL bytes may contain old writes. The storage contract does not expose them as history.

The gap is narrow but foundational

Lane gives facets

  • typed scalar replacement
  • append/delete list
  • atomic storage calls
  • separate volatile ReplicatedState

Products need

  • ordinary nested mutation
  • automatic delta + base policy
  • historical document reads
  • commit and replication as one path

Lane remains a good execution design. It is not enough as the state substrate for products and facets.

A Session is a store of entries, documents, and live task bookmarks.

Not one giant DOM. Not a bag of extension-owned repositories.

Create a durable document

// Module-level typed declaration token.
const CanvasDoc = defineDoc<CanvasState>({
  id: "@app/canvas",
  scope: "session",
  history: "latest",
  initial: () => ({ strokes: [] }),
});

// Tx resolves CanvasDoc to this Session's mutable draft.
await session.commit(tx => {
  tx.doc(CanvasDoc).strokes.push(stroke);
}, context);

CanvasDoc is the token. tx.doc(CanvasDoc) is this transaction's draft.

Expose the same document through Chord

interface CanvasService {
  readonly state: ReplicatedState<CanvasState>;
  addStroke(stroke: Stroke, context: Context): Promise<void>;
}
const Canvas = defineService<CanvasService>("@app/canvas");

// Committed source for the CanvasDoc token declared previously.
const canvasDocument = session.document(CanvasDoc);
const canvasState = replicatedState.own(canvasDocument);

env.provide(Canvas, {
  state: canvasState,
  addStroke: (stroke, context) => session.commit(tx => {
    tx.doc(CanvasDoc).strokes.push(stroke);
  }, context),
});
  • No second tracker.
  • No facet-authored delta protocol.
  • No restart reconstruction code.

Three built-in conversation documents

interface ConversationView {
  conversation: ConversationInfo;
  entries: Entry[];             // bounded active transcript
  rewindable: RewindableState; // historical fork state
  sticky: StickyState;         // inbox and present policy
  live: LiveState;             // turn, streaming, tools, collapse
}
rewindable ["s", ["model"], model]
       view ["s", ["rewindable", "model"], model]

live       ["a", ["message", ...], delta]
view       ["a", ["live", "message", ...], delta]

A fixed structural mount. No config merge, task description pass, or plugin projection.

Rewind belongs to documents

commit 100  entry E + rewindable plan.enabled = true
commit 101  live streaming progress
commit 102  rewindable plan.enabled = false

fork at E:
  rewindable → state at commit 100
  sticky     → fresh defaults
  live       → fresh defaults
  tasks      → not copied
  child      → new document IDs + initial bases
  • Bases bound replay distance.
  • Rewindable history remains while ancient forks are supported.
  • The parent and its live work remain untouched.

Storage publishes all or none. ConversationView emits one combined operation batch.

Storage chooses delta or base

interface DocumentChange {
  id: DocumentId;
  ops: readonly Op[];
  value: JsonValue; // borrowed; not serialized normally
}

if (bytesSinceBase + encodedSize(ops) < threshold)
  persist(ops);
else
  persist([["r", value]]);
  • Latest: committed base allows reclaiming the old tail.
  • Rewindable: bases accelerate reads; old addressable segments remain.
  • Chord clients still receive incremental ops.

SQLite: the long-running backend

Documents

  • metadata row
  • indexed base/delta records
  • range query for current or as-of
  • transactional latest reclamation

Tasks + entries

  • one complete row per live task
  • DELETE on retirement
  • immutable paged entry rows
  • all writes in one SQL transaction

No sidecar publication protocol. No scan of unrelated conversations or documents.

JSONL: one uniform publication rule

main.jsonl               tables + one publication marker per commit
task-<id>.jsonl          retireable task state
doc-<id>.jsonl           one file per document instance

commit                   append every sidecar first
                         append one compact main marker last
retire task              publish terminal marker → unlink task sidecar
rebase latest document   publish base marker → atomic sidecar rewrite

Sidecars are a JSONL backend decision. Harness and facet code never see them.

The benchmark changed one decision

Measured

  • 72 storage runs + 48 SQLite materialization runs validated
  • task sidecars: 1.13 MB → 59 KB after retirement
  • SQLite task deletion + checkpoint: 4.45 MB → 0.30 MB

Rejected optimization

  • JSONB replacement 10–18% slower than TEXT
  • SQL JSON patching used 2–4× CPU
  • large canvas DB+WAL: ~80 MB → ~155 MB

Persist Chord ops and periodic bases. Do not build a second op interpreter in SQL.

Years-long sessions stay bounded in memory

Session
├─ entries                         paged rows; unbounded on disk
├─ conversation A
│  ├─ active entry window          bounded
│  ├─ pi.rewindable                loaded while active
│  ├─ pi.sticky                    loaded while active
│  └─ pi.live                      loaded only while needed
├─ conversation B                 evictable while idle
├─ @app/canvas                    loaded while service is active
└─ task 91                        one live row; deleted at terminal

There is no whole-session materialization, snapshot, or subscriber payload.

Families: one typed document per task

const JobOutputDoc = defineDocFamily<JobOutput, JobInput>({
  id: "pi.job-output",
  scope: "conversation",
  history: "latest",
  owner: "task",
  initial: input => ({ command: input.command, stdout: "" }),
});

// task.id selects the family instance owned by this task
await rt.commit(tx => {
  tx.doc(JobOutputDoc, task.id).stdout += chunk;
}, context);

Terminal settlement retires the task and every task-owned family instance atomically.

Watch another task's durable output

const job = await api.task(JobKind, input, { background: true }, context);
const watch = await api.watchDoc(JobOutputDoc, job.id, context);

consume(watch.value);                    // atomic initial snapshot
watch.start((_ops, value) => consume(value));

try {
  return await api.waitForTask(job, context);
} finally {
  watch.stop();                           // idempotent, invocation-owned
}
  • Callbacks run off the Session mutation line.
  • Recovery re-enters and captures a fresh snapshot; no durable subscription cursor.
  • Retirement appears as document absence.
